# Day 36 - 混合检索（Hybrid Search）与大模型幻觉防御

## 核心知识点

### 1. 检索器的优缺点
- **纯向量检索（Dense Retrieval）**：懂语义（知道“打车”和“出行”有关），但不懂精确匹配（对数字、专有名词极度不敏感，分不清 500 和 600）。
- **纯 BM25 检索（Sparse Retrieval）**：懂精确匹配（词频匹配，找“500”特别准），但不懂语义（问“出行”搜不到“打车”）。
- **混合检索（Hybrid Search）**：两路并发检索，综合两者优势，是目前企业级 RAG 标配。

### 2. RRF（倒数排名融合）算法
- 用于合并两路检索的排名。
- 核心公式：`得分 = 1 / (k + 排名位置)`，其中 `k` 一般取 60。
- 原理：如果某文档在向量排第一，在 BM25 也排第一，它的总分就最高，稳稳被召回。

### 3. 大模型的“幻觉”（Hallucination）
- **现象**：给定的参考资料里只有“限额500元，需总监审批”，但大模型自行脑补出了“贴发票、交财务、打款”等 5 个步骤。
- **原因**：
  1. Prompt 约束太弱（没禁止发散）。
  2. 大模型的“讨好型人格”（训练时被设定为尽量提供详尽的帮助）。
- **工业级防御方案**：
  1. 使用极度严厉的 System Prompt（“绝对不要编造”）。
  2. 使用 XML 边界符（如 `<资料> ... </资料>`）明确划分资料区和问题区。
  3. 把 `temperature` 调到极低（0 或 0.1）。

## 踩坑与反思
- **核心教训**：做 RAG 应用，**“检索得准”只是第一步，“约束得住模型”才是关键**。
- 如果不加严格的 Prompt 边界，RAG 系统会变成一个“看起来很专业，但满嘴跑火车”的智障客服。
